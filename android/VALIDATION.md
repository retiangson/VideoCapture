# Android preview validation

Validated 30 October 2026 (Pacific/Auckland), version 0.2.3. Isolated API 35 x86_64 emulator; no physical phone/tablet connected. Airplane mode and Wi-Fi disabled for offline tests. Core tests assert no active network using `requireOffline=true`.

- `assembleDebug`, `assembleDebugAndroidTest`, `assemblePreview`: successful. ARM64 and x86_64 native libraries compiled; release-optimized preview is locally debug-signed.
- `lintDebug`: zero errors, 17 warnings (English-only strings, custom touch accessibility and intentional JavaScript among them). This does not establish production acceptance.
- Full offline tablet suite: **19 tests passed**, 103.291 seconds. This covers visible normal-mode startup, source-button visibility, USB picker/empty-result feedback, decoding/resume, touchscreen gestures, saved browser tabs, exact-origin browser microphone policy, MKV text cues, bundled OCR/Whisper, selected audio-track extraction, local clip export, source-only EGL/PCM recording, USB microphone-fallback rejection, and responsive layouts.
- Five startup/layout tests repeated at phone portrait (1080×2400, density 420), phone landscape (2400×1080, density 420), and the emulator's native tablet size. Prior 0.2.0 checks also covered a narrow 320 dp phone (1080×2400, density 540). They check window bounds, usable address/page areas, reachable controls, maximize/restore, real keyboard insets and rotation with the browser/transcript open. The 0.2.1 startup tests check the normal window, explicit fullscreen entry/exit and visible source buttons. Prior 0.2.0 narrow-phone checks covered primary playback/recording control bounds and actual local clip export.
- Rotation initially recreated the activity and lost the active browser. The app now handles the complete set of size-based configuration changes and reflows the current views. The regression test asserts the same browser instance and visible transcript survive both orientations.
- Manual emulator layout review covers the phone player and floating browser. The minified APK is installed and launched separately from instrumentation; first-use camera permission was accepted through the system dialog and led to visible USB-picker feedback. APK signature and 16 KB ZIP alignment are verified when packaging.
- Prior 0.1.0 native optimized speech verification transcribed the known offline video fixture: “Quick brown fox jumps over the lazy dog. Please copy this video transcript.” The native speech implementation is unchanged in 0.2.1, and core offline inference still passes instrumentation.

Headless emulator audio hardware is unavailable: browser tests assert an actual audio-only permission grant and rejection of untrusted origins, while accepting Android's `NotReadableError` after a grant. This does not prove physical browser microphone capture. Fixtures are synthetic; no real account login was used.

Physical USB/OTG capture, microphone accuracy, USB audio routing/sync, hotplug recovery, codec coverage, offline TTS voices, sustained recordings, thermal behavior and real-device performance remain unverified. Background/locked-screen recording and built-in Camera2 capture remain unimplemented. See [PARITY.md](PARITY.md).

The reported Samsung black startup occurred before opening the device picker. Version 0.2.1 changes startup/discovery UI and leaves the USB driver unchanged. The isolated emulator has no capture card; picker feedback tests validate the UI, not physical USB compatibility.

Version 0.2.2 adds an option-state test covering saved settings, fill/fit, timeline, subtitle reading, browser hide/show, transcript/navigation controls, fullscreen, accessibility On/Off descriptions, and disabled dimming. The full 17-test offline run passed before the final dimming-only change; the final targeted state/layout run verifies that last change. Windows checks also cover actual template markers/fills, playback pause/resume, fullscreen keyboard entry, browser show/hide, transcript controls and close-during-export cleanup.

Version 0.2.3 adds native single-finger double-tap entry/exit and fullscreen LIVE-caption visibility checks, plus Regular/Fill/Stretch selection, USB viewport sizing calculations, legacy Fill migration and persistence across fullscreen/recreation. Windows GPU checks validate Stretch aspect override, clearing that override for Regular, three-mode toolbar cycling, and retained mode after fullscreen/reopening. Fullscreen no longer forces Fill.

Version 0.2.4 adds Android WebView file uploads with an explicit **Copied frame / Choose files** chooser for compatible image requests. The full offline suite passed **22 tests in 80.096 seconds**, including a native touchscreen tap on an actual HTML file input, reading the uploaded PNG with JavaScript FileReader, and comparing the complete data URL against the original bytes and MIME. Additional checks cover MIME acceptance, picker failure, multiple selection, invalid URI schemes, replaced requests, cancellation and ignored late results. Build, optimized preview packaging, APK signature and 16 KB ZIP alignment passed; lint reports zero errors and 15 warnings. This adds a standard attachment workflow; it does not establish ordinary clipboard image paste support in Android WebView. Actual online ChatGPT attachment behavior still requires verification on the tablet. Windows is unchanged.

Version 0.3.0 publishes captured frames to MediaStore/Gallery before copying them, replacing the private-cache URI on the clipboard. A native Ctrl+V paste into the floating browser's contenteditable fixture now delivers an image file with the exact original PNG bytes. The file-input attachment test uses the same Gallery-backed URI. Every copied frame remains in Pictures/VideoCapture. Failed writes/publication remove the incomplete row; clipboard failure leaves the saved image available.

The complete offline tablet suite passed **25 tests in 85.501 seconds**, including Gallery paste/upload, independent tap-selected volume persistence, opacity minimum/disabled/RTL interaction, rotation-lock enable/disable/restoration, and existing media/OCR/speech/recording/browser tests. The first full run exposed a double-tap input-timing failure under emulator load; it passed in isolation, and the test now supplies explicit realistic event timestamps before the final full run. No gesture timeout was relaxed. The final build and optimized APK signature/16 KB alignment checks passed; lint reports zero errors and 17 warnings. Native vector icons and gradient surfaces were visually reviewed; no bitmap skin assets or animation loop were added. Windows build, actual playback/fullscreen/direct-slider checks and active-state rendering tests passed, and its staged publish was installed after the app was closed. LibVLC still emits the existing D3D11 thumbnail warning during synthetic playback tests. Actual Samsung ChatGPT paste and physical device rotation remain to be verified.

All nine responsive/control tests also passed at 320 dp phone portrait (19.195 seconds) and short phone landscape (20.803 seconds), including browser bounds, keyboard insets and real rotation. After a final icon-alpha correction, Gallery paste, tap-selected levels and restored rotation lock passed again (three checks, 10.462 seconds). The final minified APK was separately installed/launched and its tablet controls visually reviewed with default opacity. No tests or installation were performed on the connected physical device.
