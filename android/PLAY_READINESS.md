# Google Play readiness review

Reviewed 30 October 2026. Applies to the Android 0.4.0 source and its merged manifest. **This is a technical review, not a compliance certification or approval from Google. The preview is not ready for Play submission.**

## Release blockers

1. Publisher identity, public support contact and a published privacy-policy URL are deferred at the owner's request. The in-app Privacy & data page is processing information, not a substitute for the required published policy. The policy must describe the final build and link from both the app and Play Console. See [Google Play User Data policy](https://support.google.com/googleplay/android-developer/answer/10144311).
2. Complete and review the Data safety form against the exact dependency versions and browser behavior. **Do not select “no data collected” without reviewing ML Kit diagnostics.** Google's [ML Kit disclosure guide](https://developers.google.com/ml-kit/android-data-disclosure) lists technical device/app information, installation-scoped identifiers, performance/configuration/event metrics and related diagnostics. OCR input images and recognition results are processed on-device; that does not imply the SDK sends no diagnostics. The SDK is now initialized only after an OCR disclosure and affirmative agreement.
3. The installable preview uses this machine's debug signing key. Configure a private production upload key and Play App Signing; never commit keys/passwords. An unsigned release AAB can be built, but it is not a publishable signed release. Verify Play's device-specific download size and delivery configuration for the bundled speech model.
4. Complete Play Console declarations, content rating, target audience, app access/reviewer instructions, listing/branding and third-party license review. Check current Play SDK Index warnings and dependency guidance before release. No Play Console account state, developer verification, store declarations or server-side reviews were inspected or changed.
5. Validate the final signed release on the Samsung hardware, including microphone handoff, USB input/audio, permission denial/revocation, hotplug and lifecycle behavior. Emulator permission tests do not establish physical microphone capture. Complete a runtime test on a 16 KB-page device; ZIP/ELF alignment checks alone do not establish runtime compatibility.

## App-side checks and safeguards

| Area | Implementation / verification scope |
| --- | --- |
| Target SDK | Targets API 36. This meets the mobile new-app/update target stated in the [current target API requirements](https://support.google.com/googleplay/android-developer/answer/11926878) for August 2026. This is one submission requirement, not an approval. |
| Storage | Individual/multiple files and folders use Android's [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files). Folder grants are limited to the user-selected tree. No all-files or broad media-library read permission is added. Scans are cancellable and bounded; original files are never deleted by playlist removal/clear. |
| Sensitive permissions | Camera permission is used for selected USB video access. Audio permission is requested for selected input recording/transcription or browser voice. Purpose disclosures precede first runtime grants. Denial/back/cancel is not consent. No background recording service, accessibility service, system-wide overlay, location, contacts or installed-app inventory permission is requested. |
| Microphone ownership | UVC's unused default audio recorder is disabled. ChatGPT voice requests pause/release app audio inputs before web capture starts. The app refuses simultaneous native recording that would conflict. Native video sound/subtitle speech is paused during browser microphone use and restored afterwards. No promise is made to override another app's or the OS's exclusive microphone use. |
| Browser permissions | Audio-only grants are restricted to the exact HTTPS ChatGPT origins and matching top-page host. The lifecycle bridge uses origin-restricted AndroidX WebKit messaging, not a global JavascriptInterface. The bridge passes request/end identifiers and grant results, not audio, messages, cookies or page content. Hiding/changing/closing a tab or pausing the app stops tracked browser audio streams. Camera/arbitrary-origin capture is denied. |
| Google sign-in | Google account authorization is opened in an external browser; no user-agent spoofing, embedded Google credential entry or cookie transfer is implemented. See [Google OAuth secure-browser policy](https://developers.google.com/identity/protocols/oauth2/policies). External and embedded browser sessions are separate, so this is not a seamless sign-in bridge. |
| Transport / browser data | Cleartext navigation is disabled, Safe Browsing is enabled, and normal TLS errors retain WebView's default rejection behavior. Cookies/site storage persist for user logins. Privacy & data includes an explicit clearing action; modern WebViews use the full browsing-data API, while older WebViews clear cookies, platform web storage and HTTP cache. Android's app-storage clearing remains the complete platform-level reset. |
| Native processing | Bundled OCR/Whisper support offline media workflows. Native transcription is not sent to an app-operated server. Website uploads, messages and voice requests are processed by the chosen website under its policy. Android document/cloud providers can use their own networks. |
| Local retention | Playlist URIs, bookmarks, preferences and tab addresses remain in app storage. Android app data clearing/uninstall removes app storage. Gallery captures remain until the user deletes them separately. App backup is disabled. FileProvider is non-exported and grants access only to configured capture/export paths. |
| Packaging | ARM64 and x86_64 are included. Signature/16 KB ZIP alignment and the merged permission manifest are checked when packaging. Production signing, device-specific delivery/download sizing and physical 16 KB runtime behavior remain release work. |

Google's [Data safety guidance](https://support.google.com/googleplay/android-developer/answer/10787469) distinguishes controlled WebView collection from open-web navigation. Review the actual browser use and microphone mediation rather than assuming a blanket browser exemption. The final publisher must determine the correct declarations; none were submitted automatically.

## Boundaries

The app has no native user-account creation, advertising or developer-operated media upload backend. Third-party website accounts and their deletion are managed by those websites. This does not waive the publisher's privacy-policy, disclosure or Data safety responsibilities. The review does not cover unimplemented TV ports, another distribution store, future dependencies, modified builds, or compliance with every jurisdiction's laws.
